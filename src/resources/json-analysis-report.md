## Recommendations for Development

### Data Model Observations

1. **Flat, catalogue-style data** — this is a simple list of principles with tags for categorisation. There is no hierarchical parent-child or graph relationship between principles.
2. **Tags form a controlled vocabulary** — the 11 unique tags behave like a lookup/enum table. A normalised model would extract them into a `Tag` entity with a many-to-many join (`PrincipleTag`).
3. **Sources are semi-structured** — some entries are author names, some are generic category labels (`"Agile principle"`), and some are URLs. A richer model could split sources into `{ attribution: string, url?: string }` objects.
4. **No explicit identifiers** — principles are identified only by position in the array or by their `title`. For any API or database backing, a stable `id` (slug or UUID) is needed.
